# Jellio

Jellyfin plugin that replaces the Jellyfin web client's own rendering with a
Nuvio lookalike, backed entirely by remote sources (Stremio addons via
Gelato, debrid, usenet). No local media is ever assumed.

This is the second Jellio codebase. The original (`NoahSKipp/Jellio`)
reskins the real native Jellyfin web client with injected CSS/JS, overlaying
and augmenting native React components in place. That approach hit a hard
ceiling: native pages have to actually render correctly, and native
`ApiClient`/session state has to be correct, before any of Jellio's own CSS
or JS can act on them, and neither is fully in this plugin's control. This
codebase instead follows MonWUI/JMSFusion's real architecture: its own
persistent auth/session runtime, independent of native `ApiClient` state,
and its own directly-rendered screens fed by its own fetch calls, not by
waiting on native components to mount. Native jellyfin-web renders nothing
this plugin cares about; it is only the host page and the real Jellyfin
server API underneath.

## Working rules

These are hard rules. They apply to every session, every branch, every commit.

### Authorship

- Every commit is authored **and** committed by `Noah S. Kipp <kippnoahsamuel@gmail.com>`.
- Every commit is GPG signed with key `9D82CFAE019B44EE`.
- No `Co-Authored-By` trailers. Ever.
- No "generated by", "made by", "with help from" or any similar attribution in
  commit messages, PR bodies, code comments, docs, config files or release notes.
- Nothing anywhere in this repository names an AI assistant as a contributor.

### Branches

- Branch names describe the feature being worked on.
- Never include the word `claude`.
- Never include digits.
- Lowercase, hyphen separated. Examples: `hero-carousel`, `notification-hub`,
  `stream-picker-overlay`, `release-pipeline`.

### Commits

- Conventional commit prefixes (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`,
  `ci:`, `style:`, `test:`). The release workflow reads these.
- One logical change per commit. No mega commits.
- Commit timestamps are spread to match the real weight of the change. A CSS
  token tweak sits minutes after the previous commit. A full screen
  implementation sits hours after it. Author date and committer date are set
  together via `GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE`.
- Push with `git push -u origin <branch>`.

### Code style

- Comments are sparse. Only for genuinely non obvious blocks, and written as a
  short note to self, not as documentation prose.
- No banner comments, no section dividers, no restating what the line does.
- Match the surrounding file. C# follows the Jellyfin plugin conventions,
  frontend follows the Nuvio structure we are mirroring.

### Writing

- No em dashes anywhere. Not in code, comments, docs, commit messages, config,
  UI strings or release notes.

## Architecture

The plugin is a thin C# host: it patches a single script tag into
jellyfin-web's own `index.html` (same mechanism the original Jellio uses,
`Services/IndexHtmlPatchService.cs`) and serves its own embedded frontend
bundle from there. Everything else, session handling, data fetching,
rendering, lives in that frontend bundle, not in native jellyfin-web code.

```
frontend/runtime/auth.js   owns the token store, independent of native
                            ApiClient state. Captures a real login the same
                            way JMSFusion does: intercepting console.log for
                            jellyfin-apiclient-javascript's own
                            "Stored JSON credentials: ..." boot line, rather
                            than trusting native ApiClient.isLoggedIn(),
                            which native code only sets on its own schedule.
frontend/runtime/api.js    every server call the UI needs (System Info,
                            Views, Items, Images, User, Favorites, playback
                            URLs), built on auth.js's own headers. Nothing
                            here calls into native ApiClient.
frontend/app.js            bootstrap: hides native page content once the
                            real page has settled, mounts Jellio's own root
                            container, and owns client side routing between
                            Jellio's own screens.
frontend/screens/          one file per real screen (home, library, detail,
                            player chrome, settings, ...), each rendering
                            itself from api.js calls, not from native DOM.
```

Every screen rendering something real users depend on (native page still
loads underneath while a screen is unfinished) is how partial migration
stays safe: an unmigrated route falls back to native jellyfin-web rendering,
an unstyled but working page rather than a broken one.
